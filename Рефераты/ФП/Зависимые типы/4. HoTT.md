```scala
// 1. Структура 1-типа (группоида)
trait Groupoid[A]:
  type Id[x <: A, y <: A]
  def refl[x <: A]: Id[x, x]
  def sym[x <: A, y <: A](p: Id[x, y]): Id[y, x]
  def trans[x <: A, y <: A, z <: A](p: Id[x, y], q: Id[y, z]): Id[x, z]

// 2. Тип окружности S¹
enum S1:
  case Base

object S1:
  // 3. Абстрактный тип путей (петель) на S¹ без привязки к Int!
  // Путь p: Loop — это полиморфная функция, вычисляющаяся в любой целевой группоид.
  trait Loop:
    def apply[A](using G: Groupoid[A])(b: A, l: G.Id[b.type, b.type]): G.Id[b.type, b.type]

  // S¹ само является группоидом (свободным группоидом с одной петлёй)
  given Groupoid[S1] with
    type Id[x <: S1, y <: S1] = Loop

    def refl[x <: S1]: Loop = new Loop:
      def apply[A](using G: Groupoid[A])(b: A, l: G.Id[b.type, b.type]): G.Id[b.type, b.type] =
        G.refl[b.type]

    def sym[x <: S1, y <: S1](p: Loop): Loop = new Loop:
      def apply[A](using G: Groupoid[A])(b: A, l: G.Id[b.type, b.type]): G.Id[b.type, b.type] =
        G.sym(p(b, l))

    def trans[x <: S1, y <: S1, z <: S1](p: Loop, q: Loop): Loop = new Loop:
      def apply[A](using G: Groupoid[A])(b: A, l: G.Id[b.type, b.type]): G.Id[b.type, b.type] =
        G.trans(p(b, l), q(b, l))

  // Канонический конструктор пути: loop : Base = Base
  val loop: Loop = new Loop:
    def apply[A](using G: Groupoid[A])(b: A, l: G.Id[b.type, b.type]): G.Id[b.type, b.type] =
      l

  // 4. ПОЛНОЦЕННЫЙ УНИВЕРСАЛЬНЫЙ РЕКУРСОР (rec_S1)
  // Принимает целевой группоид A, точку b: A и петлю l: b =_A b.
  // Возвращает пару: функцию на точках (S1 => A) и действие на путях (ap_f).
  case class RecResult[A](using G: Groupoid[A])(
    val onPoint: S1 => A,
    val onLoop: Loop => G.Id[?, ?]
  )

  def rec[A](using G: Groupoid[A])(b: A, l: G.Id[b.type, b.type]): (S1 => A, Loop => G.Id[b.type, b.type]) =
    val f: S1 => A = { case S1.Base => b }
    val apF: Loop => G.Id[b.type, b.type] = p => p(b, l)
    (f, apF)
```

```scala
// Эквивалентность типов (путь во Вселенной Type согласно унивалентности)
case class Equiv[X, Y](to: X => Y, from: Y => X)

// Тип Вселенной (0-типов), где пути — это биекции/эквивалентности
type Universe = Any

given Groupoid[Universe] with
  type Id[X <: Universe, Y <: Universe] = Equiv[X, Y]
  def refl[X <: Universe]: Equiv[X, X] = Equiv(identity, identity)
  def sym[X <: Universe, Y <: Universe](e: Equiv[X, Y]): Equiv[Y, X] = Equiv(e.from, e.to)
  def trans[X <: Universe, Y <: Universe, Z <: Universe](e1: Equiv[X, Y], e2: Equiv[Y, Z]): Equiv[X, Z] =
    Equiv(e1.to.andThen(e2.to), e2.from.andThen(e1.from))
```

```scala
@main def proveFundamentalGroup(): Unit =
  val G_S1 = summon[Groupoid[S1]]
  val G_U  = summon[Groupoid[Universe]]

  // Определяем петлю во Вселенной: автоморфизм (x => x + 1) на типе Int
  val shiftEquiv: Equiv[Int, Int] = Equiv(_ + 1, _ - 1)

  // Применяем универсальный рекурсор S1.rec к Вселенной типов!
  // Получаем отображение code: S1 => Universe и его действие на путях transport
  val (code, transport) = S1.rec[Universe](Int, shiftEquiv)

  // Сконструируем произвольный сложный путь на окружности:
  // p = loop ∙ loop ∙ loop⁻¹ ∙ loop
  val p: S1.Loop = G_S1.trans(
    G_S1.trans(G_S1.trans(S1.loop, S1.loop), G_S1.sym(S1.loop)),
    S1.loop
  )

  // Вычисляем число оборотов (encode), транспортируя 0 вдоль пути p:
  val equivalenceAtP: Equiv[Int, Int] = transport(p).asInstanceOf[Equiv[Int, Int]]
  val windingNumber: Int = equivalenceAtP.to(0)

  println(s"Вычисленное число оборотов для p: $windingNumber") // Выведет: 2
```

Транспорт элемента $b : P(\text{base})$ вдоль разных путей на окружности приносит его в **разные значения** одного и того же типа $P(\text{base})$:

- Вдоль пустого пути `Refl`: $\text{transport}^P(\text{Refl}, b) = b$.
- Вдоль петли `Loop`: $\text{transport}^P(\text{Loop}, b) = f(b)$, где $f : P(\text{base}) \to P(\text{base})$ — нетривиальная биекция, заданная расслоением $P$.
- Вдоль двойной петли `Loop ∙ Loop`: $\text{transport}^P(\text{Loop} \cdot \text{Loop}, b) = f(f(b))$.

Чтобы зависимая функция $g : (x : S^1) \to P(x)$ была корректно определена, значение $b = g(\text{base})$ должно быть **инвариантно** относительно обхода по петле `Loop` (то есть $f(b)$ должно быть соединено путём $l$ с $b$).

# Что именно нумеруется целыми на S² — и почему это не «то же самое», что на S¹

Короткий ответ: **на S¹ целые нумеруют *пути* (1-мерные объекты), а на S² — *отображения сферы* (2-мерные объекты)**. Это разные вещи, хотя обе группы изоморфны ℤ. Ниже — визуализация и различие.

## 1. Визуализация: что такое «2-номер намотки»

### S¹: намотка верёвки вокруг столба

Возьмите **верёвку** (отрезок `[0,1]`) и намотайте её на **столб** (окружность S¹). Концы верёвки склеены в базовой точке. Число «оборотов» — целое:

- `0` — верёвка лежит на столбе и стягивается в точку;
- `+1` — один оборот против часовой;
- `+2` — два оборота;
- `−1` — один оборот по часовой.

**Объект намотки — 1-мерный: петля `S¹ → S¹`.** Целое — это `π₁(S¹)`.

### S²: обмотка сферы-«мяча» сферой-«плёнкой»

Теперь возьмите **сферу-плёнку** (границу шара, `S²`) и **оберните её вокруг сферы-мяча** (тоже `S²`), зафиксировав северный полюс в базовой точке. Тоже получаются целые числа:

- `0` — плёнка стянута к точке у северного полюса (или «сдулась» — вся плёнка в одну точку);
- `+1` — плёнка **обернула мяч ровно один раз** (как вторая кожа на мяче, orientation-preserving);
- `+2` — обернула дважды (плёнка «намотана» как двойная оболочка);
- `−1` — обернула один раз с **вывернутой ориентацией** (как вывернутая наизнанку кожа);
- `−2` — дважды с вывернутой.

**Объект намотки — 2-мерный: отображение `S² → S²`, фиксирующее точку.** Целое — это `π₂(S²)`.

### Ключевая визуализация — «степень отображения» (degree)

Представьте, что вы **красите мяч** и смотрите на прообраз каждой точки:

- степень `0`: прообраз точки — **пусто** или замкнутая кривая (не покрывает мяч);
- степень `+1`: у каждой точки мяча ровно **один** прообраз-прототип (биекция);
- степень `+2`: у каждой точки мяча **два** прообраза, оба с одинаковой ориентацией;
- степень `−1`: **один** прообраз, но ориентация вывернута (как зеркальное отражение).

Формально: возьмите регулярное значение `y` на сфере-мяче. У него конечное число прообразов `x₁,…,xₖ`. Каждому припишите `±1` по знаку якобиана отображения в этой точке. **Сумма `Σ ±1` и есть целое число** — степень. Она не зависит от выбора `y`. Это и есть «2-номер намотки».

## 2. Чем это принципиально отличается от S¹

### Разная размерность объекта

| | S¹ | S² |
|---|---|---|
| Что намотано | верёвка `S¹` (1-мерная) | плёнка `S²` (2-мерная) |
| На что намотано | столб `S¹` | мяч `S²` |
| Отображение | `S¹ → S¹` | `S² → S²` |
| Группа | `π₁ = ℤ` | `π₂ = ℤ` |

Обе группы изоморфны ℤ, но **элементы групп — объекты разной размерности**. Это как «число 3» в задаче про яблоки и «число 3» в задаче про кубы: значение то же, а объекты, которые считаются, разные.

### Что *не* работает на S² (и работало на S¹)

- **π₁(S²) = 0.** Любая верёвка на мяче стягивается в точку — на мяче нет «дырки» (как у тора), за которую можно зацепиться. На S¹ верёвка зацепляется за саму окружность. **Поэтому на S² нет аналога `Loop`** — нет 1-мерной намотки. Ваш код это и отражает: в `Path[S2, Base, Base]` есть только `Refl`.
- **На S¹ π₂ = 0.** Любая плёнка на столбе стягивается (столб «тонкий»). На S² плёнка зацепляется за 2-мерную «дырку» — за сам мяч.

Это и есть знаменитый сдвиг: `π₁(S¹) = ℤ`, `π₂(S¹) = 0`, `π₁(S²) = 0`, `π₂(S²) = ℤ`. Целые «переехали» с размерности 1 на размерность 2.

### Почему это не «свелось к тому же самому»

Если бы S² давала *тот же* изоморфизм, что S¹, это означало бы `π₁(S²) = ℤ`. Но `π₁(S²) = 0` — верёвки на мяче стягиваются. Целое на S² живёт **на два порядка «толще»**: чтобы его увидеть, нужно намотать 2-мерную плёнку, а не 1-мерную верёвку. В вашем коде это видно буквально:

- S¹: `Loop : Path[S1, Base, Base]` — **1-клетка**;
- S²: `Surf : Path[Path[S2, Base, Base], Refl, Refl]` — **2-клетка** (путь между путями).

`Surf` — не путь между точками, а путь между *путями-рефлексивностями*. Именно поэтому `winding2` в примере выше рекурсирует по `Path[Path[...]]`, а не по `Path[...]` — уровень вложенности выше на единицу.

### Аналогия с «зацеплением»

- **S¹**: верёвка **обвивает** столб. Число — сколько раз обвила. Можно почувствовать, потянув за концы: сопротивление = намотка.
- **S²**: плёнка **обтягивает** мяч. Число — сколько слоёв плёнки (с учётом ориентации). Потянуть «за край» нельзя — края нет (плёнка замкнута), но можно «сдуть» плёнку в точку ровно тогда и только тогда, когда степень `0`.

Ещё аналогия: **расчёска на сфере**. По теореме о причёсывании ёжа, любое векторное поле на S² имеет нуль — но это про `π₂`-косвенное. Более прямая: **сферическая карта звёздного неба** (отображение `S² → S²`, сопоставляющее направлению взгляда точку на небесной сфере). Её степень — сколько раз «небо» накрывает сферу: `0` — карта схлопнута, `+1` — нормальный атлас, `−1` — атлас с зеркалом, `+2` — двойное покрытие.

## 3. Как это соотносится с вашим кодом

В `piTest`:

```scala
type TwoLoop = Path[Path[S2, Base, Base], Refl, Refl]
```

`TwoLoop` — это **не** путь между точками S². Это путь между **путями-рефлексивностями** `Refl : Base = Base`. Содержательно `TwoLoop` — это в точности «отображение `S² → S²`, фиксирующее северный полюс» (по определению S² как HIT с точкой и 2-клеткой). Так что `winding2 : TwoLoop → ℤ` — это буквально **степень отображения**, «сколько раз плёнка обернула мяч».

`surlPow(n)` строит отображение степени `n` (склейка `|n|` копий `Surf`, со знаком). `winding2(surfPow(n)) == n` — проверка, что степень этого отображения равна `n`. Это прямой аналог того, что `winding(Loop^n) = n` в S¹, но на уровень выше: `Loop` (1-клетка) заменился на `Surf` (2-клетка).

Итог: **целые числа на S² — это степени отображений `S² → S²` (сколько раз плёнка обернула мяч с учётом ориентации), а не числа оборотов верёвки.** То, что обе группы изоморфны ℤ — совпадение малых размерностей (и следствие теоремы Гуревича/Фрейденталя для сфер); для S³ уже будет `π₃(S³) = ℤ`, но `π₄(S³) = ℤ/2` — и «одинаковость с ℤ» сломается.
